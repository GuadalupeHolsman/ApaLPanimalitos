Sistema de diseño

Esta página documenta las decisiones definidas en la Etapa 2 y su implementación como código en la Etapa 3: variables de diseño, escalas, componentes y estructura de layout. Todo lo que se ve en el resto del sitio se construye a partir de estos tokens.

Estructura de layout y responsive

BreakpointAnchoComportamiento principal
Base (mobile)< 600px1 columna en GrillaAdopcion. Menú colapsado en ícono de hamburguesa. BarraFiltros colapsada (elemento <details>).
Tablet≥ 600pxGrillaAdopcion pasa a 2 columnas. Menú se expande horizontalmente.
Escritorio≥ 1024pxGrillaAdopcion pasa a 3 columnas. BarraFiltros visible de forma permanente en columna lateral (3/12).

El layout macro de cada página se resuelve con CSS Grid (.pagina, .grilla-adopcion-layout, .grilla-adopcion, .pie-pagina__grid). Flexbox se reserva para microcomposición: alineación de la barra de navegación, orden de elementos dentro de una tarjeta y agrupación de botones.

Container queries: .tarjeta-animal declara container-type: inline-size. Cuando su contenedor supera 420px de ancho (por ejemplo, en la sección de destacados del inicio, con 2 columnas anchas), la imagen se ubica al costado del contenido; en la grilla de adopción de 3 columnas, donde cada tarjeta es más angosta, la imagen permanece arriba — independientemente del ancho del viewport.

Antecedente: inconsistencias evitadas

El análisis de referencia de la Etapa 1 detectó tres problemas que este sistema corrige explícitamente:

  • Grises de texto sin documentar → acá solo existen --color-texto y --color-texto-suave.
  • Dos familias tipográficas combinadas sin escala clara → una sola familia (Raleway) con cuatro tamaños semánticos.
  • Tres variantes de botón sin razón funcional → un sistema único de dos botones (.btn-primario, .btn-secundario).
